Pine & Ember

§1

Principles

Four rules that explain every other decision on this page.

Health-oriented, not SaaSTeal-green + warm terracotta + warm-neutral grays — deliberately not the generic gray/blue admin-panel look.
One system, two registersCustomer pages run spacious and warm; doctor/admin pages run dense and clinical. Same tokens throughout — see Density.
Color is never aloneEvery status pairs a color with an icon and a text label — for colorblind users, and because it also has to survive black-and-white print.
Tokens over hexComponents consume the tokens below, not ad-hoc values. An August 2026 audit of the whole src/ tree found exactly one raw-color offender in three figures of components — that's the bar.
§2

Color

Four primitive ramps for UI chrome, plus theme-aware semantic tokens that actually carry meaning. Toggle dark mode in the sidebar — every swatch below is a live CSS variable, not a screenshot.

Primitive ramps

Static hex, identical in light and dark — components reach dark-mode contrast with explicit overrides, not a ramp swap.

Pine — primary50 → 950
Sand — neutral0 → 950
Ember — warm accent50 → 900
Garnet — destructive50, 600 → 800

Semantic role tokens

Each role is a text / tint / border triple that flips with the theme. These — not raw Pine/Sand — are what alerts, badges, and validation states should reference.

Temperature tiers

A dedicated 5-step clinical scale, distinct from warning/danger — a reading needs finer gradation than "ok vs. not ok." Drives the dashboard hero, badges, and chart tooltips.

§7

Cross-origin parity: Keycloak

Keycloak's hosted login pages run on a separate origin the app can't theme directly — deploy/keycloak/themes/thermometer/login/resources/css/login.css hand-mirrors these exact tokens on top of PatternFly.

No shared token file crosses that origin boundary, so this mirror drifts silently if a token here changes and the CSS isn't updated in the same pass. Bugs found and fixed while building this parity, all from the same root cause — PatternFly draws its own decorative :before/:after border layer on top of whatever we style:

  • Password field's show/hide button — was PatternFly's stock dark "control" skin, now a merged part of the input with a Sand icon that turns Pine on hover.
  • A stray colored line under every text field, from PatternFly's own unthemed validation-indicator pseudo-element.
  • The same toggle button's pseudo-element also grew a green bottom shadow on hover — same overlay pattern, different element.

All three fixed the same way: neutralize the pseudo-element (content: none) rather than chase its separate color variables. Any new PatternFly element styled in this theme should be checked for the same pattern first.

§8

Accessibility & print

Non-negotiables, not aspirations.

Status = color + icon + textNever color alone, everywhere on this page.
Reduced motionEvery animation on this page (and in the app) respects prefers-reduced-motion: reduce.
PrintThe doctor's clinical report forces a light, high-contrast token set regardless of active theme, hides chrome, and forces tier/status fills to print — they carry meaning.
FocusEvery interactive control shows shadow-focus (or the Keycloak-side teal ring) — try tabbing through the buttons above.
Source of truth lives in code, not here — fe/tailwind.config.js, fe/src/index.css, deploy/keycloak/themes/thermometer/login/resources/css/login.css. This page mirrors those files; if they disagree, the files win, and this page is out of date until fixed. Full prose version: DESIGN_SYSTEM.md in the project root.
