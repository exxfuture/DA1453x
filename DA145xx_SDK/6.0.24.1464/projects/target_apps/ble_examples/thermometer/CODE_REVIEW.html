Cross-cutting themes

Two contexts, one set of variables (firmware)

FW-02, FW-03 and FW-04 are one underlying gap: state shared between the I2C interrupt and the BLE task loop is neither volatile nor protected, and cleanup order assumes no interrupt can land in between. Fix them together and add a pure, host-testable decision function (FW-15) so the state machine has coverage.

Local-dev defaults are the only deployment that exists

INF-01, INF-02, INF-03 and INF-18 all stem from a single docker-compose.yml that is honest about being for a laptop but has no hardened sibling, no reverse proxy and ports on 0.0.0.0. A production override plus a Caddy service closes most of it.

Contracts defined more than once

The measurement envelope exists in Go, Java and TypeScript (INF-07); the tier list exists twice in the backend (BE-08); role checks are copied into eight controllers (BE-17); I2C constants live in two headers (FW-07). Each is small, but together they are where the next silent desync will come from.

Documentation drift despite a strict docs rule

CLAUDE.md requires docs to be current at all times, yet the V1 migration header contradicts the README (BE-11), rollout comments describe a status that is never written (BE-06), the gateway README overstates auth (INF-04), and the README's structure tree omits Eclipse/ and the design-system files (FW-16).

Nothing but firmware is gated by CI

Backend, frontend and gateway all have real test suites that only run when a developer remembers (INF-06). Combined with 390 tracked build artifacts and no .gitignore (FW-09 / INF-08), the repository's hygiene lags the quality of its code.

What is done well

  • Firmware: fully asynchronous, interrupt-driven AHT20 driver with no polling; pure codec isolated in codec.h and unit-tested on the host; careful sleep and power design with the reasoning written down.
  • Backend: authorization centralised in DeviceAccessGuard; enumeration-safe 404s; batched queries in hot paths; constant-time collector-token compare; idempotent MQTT ingest; RbacIT and IngestPipelineIT run against real Postgres and Mosquitto via Testcontainers.
  • Deploy: Keycloak public client with PKCE S256, no direct access grants, scoped redirect URIs; CSS-only login theme on the stock parent so Keycloak upgrades don't fork templates; backend image is multi-stage and non-root.
  • Gateway: a Source interface cleanly separates the unimplemented BlueZ path from the simulator; envelope, simulator and token packages have targeted unit tests.
  • Honesty: every security shortcut found is already named as a known gap in deploy/README.md, proposals.md or ARCHITECTURE_V3.html §11. The work is closing gaps, not discovering them.
  • Frontend: 75 passing vitest tests over extracted pure modules; the IEEE-11073 decoder is deliberately ported byte-for-byte from a proven implementation to sidestep a known vendor bug, with a regression test guarding it.

Firmware (C, DA1453x SDK6) 16 findings · 4 high 7 medium 5 low

Scopesrc/, build.sh, tests/, Eclipse/

The measurement pipeline is well engineered for an embedded BLE context: the AHT20 driver is fully asynchronous and interrupt-driven, codec.h cleanly isolates pure host-testable logic from SDK code, the sleep and power design is thoughtful and well commented, and the codec tests cover meaningful edge cases. The risks cluster in two themes. First, the async multi-context design introduces real ISR/task races (FW-02, FW-03, FW-04), compounded by -flto. Where

  • Eclipse/.cproject (DA14585 configuration, no chip macro defined)
  • sdk/platform/arch/arch_api.h:138-181

FW-02 high correctness fixed

Disconnect handler cancels timers before clearing the connection guards, letting an in-flight I2C ISR re-arm a timer

Where
  • src/thermometer.c:649-661 (user_app_on_disconnect)
  • src/thermometer.c:528-540 (user_htpt_ind_cfg_ind, correct order)

Problemuser_app_on_disconnect() calls stop_temp_timer() first and only then sets indications_enabled = false and current_conidx = GAP_INVALID_CONIDX. Every I2C-ISR callback (on_trigger_done, on_read_done → handle_sample_done) gates on those two variables. If the I2C interrupt fires in the window between the two statements, the guards still read as connected and handle_sample_done() calls app_easy_timer() again, re-arming a timer that was just cleaned up. user_htpt_ind_cfg_ind() does it in the right order.

Why it mattersLeaks or resurrects an app_easy_timer pool slot right after disconnect on a chip with a small fixed pool that this app already uses heavily.

RecommendationClear current_conidx and indications_enabled before calling stop_temp_timer(), matching user_htpt_ind_cfg_ind().

Resolutionfixed — user_app_on_disconnect() clears indications_enabled / current_conidx before stop_temp_timer(), and stop_temp_timer() itself runs inside GLOBAL_INT_DISABLE/RESTORE.

FW-03 high correctness fixed

State shared between I2C ISR context and BLE task context is not volatile

Where
  • src/thermometer.c:100-130

Problemcurrent_conidx, indications_enabled, s_pending_temp_x100, s_measurement_pending, s_samples, s_sample_count, s_sample_attempts, s_consecutive_fail_cycles and the timer handles are written from I2C hardware-interrupt callbacks and read from task-context timer callbacks (the file's own flow comment at lines 217-240 documents this), yet none is volatile. The SDK marks equivalent ISR-shared state volatile (e.g. i2c.c:137).

Why it mattersbuild.sh compiles with -flto -Os, which gives the compiler whole-program visibility and makes caching or reordering of these accesses realistic rather than theoretical.

RecommendationMark every variable touched from both contexts volatile, or hand the result across contexts inside an explicit critical section.

Resolutionfixed — Every ISR/task-shared variable (guards, sample buffer and counters, pending result, the three ISR-armed timer handles) is volatile; the aggregator receives a snapshot copy.

FW-04 high correctness fixed

Button-press ISR reconfigures the I2C pads with no exclusion against an in-flight transaction

Where
  • src/thermometer.c:490-510 (app_button_press_cb → periph_init)
  • src/platform/user_periph_setup.c:60-86 (set_pad_functions)

ProblemEvery button press (WKUPCT interrupt) unconditionally calls periph_init() → set_pad_functions(), which calls GPIO_ConfigurePin() on the I2C SCL/SDA pads. This is the SDK's hibernation-wake boilerplate, but none of the SDK examples it was copied from drive an active I2C sensor. A press during an AHT20 trigger/read reconfigures the pads mid-transaction.

Why it mattersCan corrupt the in-flight I2C transaction or leave the bus in an undefined state, undermining the otherwise careful async driver.

RecommendationSkip pad reconfiguration when a sample is in flight (s_sample_attempts > 0 or the read timer is armed), or move the work to the debounced app_button_wakeup_cb() main-loop callback.

Resolutionfixed — The driver exposes i2c_temp_sensor_busy() (volatile flag raised for the lifetime of every transaction); set_pad_functions() skips the SCL/SDA pads while it is set.

FW-05 medium security fixed — needs hardware validation

No pairing or encryption required to read live temperature data

Where
  • src/config/user_config.h:337-355 (DEF_SEC_REQ_NEVER)
  • src/config/user_config.h:461-510 (GAP_AUTH_NONE, GAP_NO_SEC)

ProblemThe peripheral never requests security and the HTP GATT database is built with sec_req = GAP_NO_SEC, so any central in range during the advertising window can connect, enable indications and read the wearer's temperature stream in plaintext.

Resolutionfixed — needs hardware validation — HTP service created with SRV_PERM_UNAUTH (app_set_prf_srv_perm) and DEF_SEC_REQ_ON_CONNECT: Just Works pairing without bonding on every connection, link encrypted before any temperature flows.
